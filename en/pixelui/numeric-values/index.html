Numeric Values

Numeric Values
Docs home Quick start Architecture Lifecycle GitHub
中文English

PixelUI separates numeric presentation from component drawing. The numeric APIs below provide validated ranges, allocation-free formatting, bindings, and edit transactions.

Range and normalization

API Signature Description
Constructor constexpr NumericRange() Creates the default range [0, 100] with step 1.
Static factory static constexpr bool tryCreate(int32_t minimum, int32_t maximum, int32_t step, NumericRange& output) Validates minimum <= maximum and step > 0. On success, writes the range to output and returns true.
Getter constexpr int32_t minimum() const Returns the lower bound.
Getter constexpr int32_t maximum() const Returns the upper bound.
Getter constexpr int32_t step() const Returns the step size.
Constraint constexpr int32_t clamp(int32_t value) const Clamps a value to the closed interval [minimum, maximum].
State query constexpr bool canIncrement(int32_t value) const Reports whether the clamped value is below the upper bound.
State query constexpr bool canDecrement(int32_t value) const Reports whether the clamped value is above the lower bound.
Arithmetic constexpr int32_t incremented(int32_t value) const Adds one step with overflow protection and upper-bound saturation.
Arithmetic constexpr int32_t decremented(int32_t value) const Subtracts one step with overflow protection and lower-bound saturation.
Free function constexpr uint32_t normalizeToExtent(const NumericRange& range, int32_t value, uint32_t extent) Maps the value’s position in the range to [0, extent] with nearest-integer rounding.

clamp(), canIncrement(), canDecrement(), incremented(), and decremented() are saturating. An uneven final step lands directly on the boundary. normalizeToExtent(range, value, pixels) maps a clamped value to an integer pixel extent with nearest-integer rounding. These operations are safe across the full INT32_MIN to INT32_MAX range.

tryCreate() returns false for minimum > maximum or step <= 0. Check the result before retaining or passing the range.

Formatting

NumericFormatter formats the value supplied to each call. Built-in policies cover integers, zero padding, scaled integers, suffixes, and percentages:

Formatting is allocation-free. format() returns false when the formatter is invalid or the destination is too small; a non-empty destination is reset to an empty string on failure. Use FixedBufferWriter::appendInteger() to compose text such as current/total.

The formatter stores only a function pointer and a non-owning context pointer. Every referenced format object, suffix string, percentage range, or custom context must outlive all calls through that formatter. A local formatter is safe for immediate formatting; a formatter retained by a Widget or queued Popup must refer to static storage or persistent App members.

Declare retained dependencies before their formatter so reverse member destruction keeps them alive:

Binding and edit session

ValueEditorBinding defines a non-owning read, write, and notification boundary. ValueEditSession stores the transaction’s original value, draft value, and editing policy.

With CommitOnConfirm, draft changes remain inside the session until commit() writes and notifies; cancel() discards the draft. With Live, each successful setDraftValue() writes and notifies immediately; cancel() restores the original value and notifies that restoration. A session constructed from an initial integer has no external binding but follows the same draft/commit/cancel path.

Operation CommitOnConfirm Live
setDraftValue(value) Update only the draft Write, notify, then update the draft
commit() Write and notify if changed; make draft the new original Make the current draft the new original
cancel() Discard the draft Restore and notify the original value if changed

All three operations return false when the session is invalid or a required write fails. A failed write preserves the current transaction state; the caller should keep the editor open or restore its visible controls from draftValue().

Binding value and changed contexts are non-owning and must outlive the session and every operation performed through it. A Popup request that copies the binding extends this requirement through both its pending and active lifetime.

Component examples

  • NumScroll uses NumericRange for stepping and NumericFormatter for labels. Configure it with setRange(min, max, step) or setRange(range), followed by setFormatter(formatter). Configure zero padding through the formatter.
  • PopupProgress maps LEFT/RIGHT through range.step(), normalizes only the bar geometry, and delegates displayed text to the formatter.
  • PopupValueDigits uses a ValueEditSession; construction leaves the external value unchanged. SELECT on a digit finishes that digit’s local edit while keeping the session open for other digits. The OK button commits the whole session; CANCEL or BACK cancels it.
